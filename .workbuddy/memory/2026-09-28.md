## 21:45 · AI 集成加载慢排查 + LLM 思维链 P0 修复
- 用户反馈"AI 集成加载非常慢"。实测定位：页面数据接口全部 20-80ms（健康），
  **慢在 LLM 分析链路**——`/intel/analyze/{symbol}` 修复前 25.3s（白等后降级 local），
  并发/长上下文场景最坏 128s / 246s 超时，结果仍是 local。
- **根因**：推理型模型（cn:glm-5.3-flash）在长上下文下思维链爆炸——6402 input tokens 时
  思维链 12,530 字符（4085 tokens），max_tokens=900/4096 全被烧光 → finish_reason=length、
  正文 0 字符 → 每次分析必失败。短 prompt 时思维链仅 1,316 tokens（所以小测试看起来正常）。
- **修复（3 处，全部实测验证）**：
  1. `ai_analyst._llm_call` 新增 `reasoning_effort` 可选参数（payload 透传）；
  2. `intel._llm_analysis`：max_tokens 900→2000 + `reasoning_effort="low"` + timeout 90s；
     同款修复应用到 `intel.ai_scrape_companies`（6144 预算两处调用）；
  3. `ai_analyst.analyze_with_llm`（行情页 AI 报告）：max_tokens 3000 + `reasoning_effort="low"`。
  4. `intel.verify_due_analyses` 重构三段式：报价网络调用移出 SQLite 写事务（原来最多阻塞写锁 8×秒级）。
- **参数实测结论（网关 16689，cn:glm-5.3-flash，长上下文）**：
  `reasoning_effort:"low"` ✅ 15.9s/finish=stop/正文 794 字符/思维链 70 tokens；
  `thinking:{"type":"disabled"}` ❌ 不透传；`enable_thinking:false` ❌ 不透传。
- **修复后端到端**：analyze/MSFT = 15.4s，engine=llm，带真实事件引用；页面接口 14-20ms。
- **并行会话覆盖事故**：修复第一版（max_tokens=4096）刚写完即被并行开发会话（occurred_at 功能）
  覆盖回 900——多会话同时改 intel.py 会互相覆盖，改完必须立即验证 + 重启。
