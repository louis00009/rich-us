### ⚠️ 本轮挖出一个既有严重缺陷（值得记住）
**`alerts.py` 的技术类提示通道一直是死的。**
`from datetime import datetime as _dt` 使 `_dt` 是**类**而非模块，
`_dt.timedelta` 恒抛 `AttributeError`；而该行原本写在 `try/except: pass` 里 →
异常被吞 → **`_tech_alerts()` 从未执行过**，52周高低/放量/跳空/RSI/摆动
全部失效（只有日内急涨跌 + 新闻两类在工作）。
本次并行化时把该行移出 try，缺陷立刻暴露。修复：`timedelta as _td`。
验证：修复后 `scan(force=True)` → scanned=12 / candidates=16 / created=6 / 18.8s
（此前是「跑 102s 但技术类候选恒为 0」）。

**这是「静默吞异常掩盖代码缺陷」的实证案例**，也印证了 B 类里 `_silent()` 的价值。
排查手法：**把可疑的 `try/except: pass` 临时去掉，看是否立刻抛异常** ——
比读代码快得多。
