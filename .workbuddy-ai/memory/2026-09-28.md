## 用户报障：点「AI 深度分析 · CHTR」弹窗根本弹不出来，只有很小一块

### 根因（真实浏览器复现 + 量化）
榜单多选工具条 `SelectionToolbar.tsx` 的容器是
`sticky top-0 z-20 … backdrop-blur`，而 `<Modal>` 原本**渲染在它的 DOM 子树里**。

`backdrop-filter`（同 `filter` / `transform` / `perspective` / `will-change` / `contain`）
会让该元素成为 **`position: fixed` 后代元素的「包含块」**。于是 Modal overlay 的
`inset-0` 不再是视口，而是**那条工具栏的盒子**：

| | 修复前 | 修复后 |
|---|---|---|
| 视口 | 1662 × 1104 | 1662 × 1104 |
| 弹窗 rect | `x=529 y=715 w=860 h=315` | `x=401 y=48 w=860 h=931` |
| 含义 | 跑到页面下方、困在工具栏里 | `py-12` 贴视口顶 + 水平居中 |

`y=715` 恰好 = 工具栏自然位置 667 + `py-12`(48)，是「包含块被换成工具栏」的铁证。

### 修法
`components/ui.tsx` 的 `Modal` 改用 **`createPortal(…, document.body)`**。
一次修好所有同类场景（工具条、`Layout` 的 sticky 头部、图表 tooltip 等任何
带 backdrop-blur/transform 的祖先）。这与 `InfoTip.tsx` 已有的修法**同一套路**
（那里是被表格 `overflow-x-auto` 裁掉气泡）。

- 加了 `typeof document === 'undefined'` 兜底：SSR 下若有人传 `open=true` 不至于炸整页
  （正常 `open=false` 已提前 `return null`）。
- 空值细节：`[role=dialog]` 是**内层面板**，overlay 才是它的父节点 ——
  判断「是否 portal 到 body」要写 `d.parentElement?.parentElement === document.body`。

### 踩坑：DOM 选择器取到了最内层
「重点关注池」这个字符串同时出现在 Card 根节点、标题 wrapper、标题 `<span>` 的祖先链上。
我一开始写 `filter(...).pop()` 取**最后一个**（最内层，只有标题没有表格）→ `querySelectorAll('tbody tr')` 恒为 0，
脚本报 `no-watchlist-row`，**看起来像自选池是空的**（我一度去查 `/api/market/quote`，实测返回 12 条正常）。
→ 正确写法：取「innerText 含该词 **且** 真的含 `tbody tr`」的那一层（`cards.find(d => d.querySelector('tbody tr'))`）。
**教训：`filter().pop()` 在嵌套同名文本上必错；断言要绑到「有实际内容」的元素上。**

### 踩坑二连：截图取证时定位不到卡片
